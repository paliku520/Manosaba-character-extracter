# 回归测试

在仓库根目录运行，Python 环境需先安装 `requirements.txt` 中的依赖，Node 需支持内置测试运行器：

```powershell
python -B -m unittest discover -s tests -v
node --test tests/test_frontend.cjs
```

测试在系统临时目录中生成设置、缓存、预设和 PNG，不读取真实游戏，也不会修改用户配置。
Python 测试覆盖取消与缓存清理的线程交错、缓存源文件失效、设置并发与原子保存、导出故障和部分成功、合成请求乱序与共享画布、缩略图透明度、文件定位锁及预设文字配置。
Node 测试通过隔离环境加载实际前端和主进程代码，覆盖静默更新、确认框关闭、数据目录、后端启动/管道错误，以及窗口设置保存后的退出顺序；不要求启动 Electron。

角色导出内部返回值已统一为 `{count, files, errors, output_dir}`；预览 PNG 导出返回 `{count, errors, output_dir}`。
全部失败或空结果发送 `export_error`，部分失败同样提示错误并提供实际成功数量；只有实际写出图片才累计一次导出。
旧版角色缓存缺少源文件指纹时会自动重新提取一次，之后继续复用有效缓存。

游戏素材抽样和真实 Electron 生命周期验证需要另外运行集成测试。
Windows 上可额外设置 `MCE_TEST_MAKENSIS` 为 NSIS 编译器绝对路径、`NSISDIR` 为其工具目录，再运行上述 Python 命令。
此时会编译并运行只含备份／还原宏的临时测试程序，验证成功、复制失败保留备份，以及失败停止后恢复先前移动的数据；所有文件操作均在临时目录，未设置编译器时自动跳过。
这些测试不会运行应用的实际安装器或卸载器；完整发行安装包仍需另外验证。
