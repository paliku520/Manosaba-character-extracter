# 导出背景素材

在「背景素材」页选择游戏根目录、`backgrounds` 目录或其分类目录，程序会自动列出资源包。无需先加载角色，也不依赖「自动查找 characters 目录」设置。

## 选择和导出

1. 点击「加载背景目录」，或在背景页把游戏目录拖入窗口。
2. 从分类下拉选择场景背景、CG 插图、演出素材或全部分类；使用搜索框按资源相对路径筛选。
3. 勾选素材。「全选当前列表」只选择当前可见项，跨分类/搜索保留选择；「取消全选」清除所有选择。
4. 点击素材行查看单个资源包的首张可用图片；点击勾选框只改变导出选择。素材行也支持聚焦后按 Enter 或空格预览。
5. 可点击「加载背景目录」右侧的「预热全部」，为全部已加载素材生成预览缓存。分类和搜索不会缩小预热范围，已有勾选不会改变。任务提供进度和取消，已完成的缓存会保留；再次预热会复用缓存。
6. 点击「导出所选」批量导出选中资源包的全部图片。

默认显示场景背景，CG 和演出素材可能包含剧透。预览最长边限制为 1280 像素，图片下方显示原始尺寸和包内图片数量。导出为原始尺寸 PNG，与角色预览/导出画质设置独立。

例如资源包 `mainbackground/1_1.bundle` 中的 `Background_001_001` 导出到：

```text
output/backgrounds/背景/Background_001_001.png
```

输出跟随设置中的输出目录，所有分类和资源包的 PNG 平铺在同一个 `backgrounds/背景` 文件夹，不再创建分类或资源包子目录。同名文件自动添加 `_1`、`_2` 等后缀，已有图片不会被覆盖。图片名称中的 Windows 非法字符和保留设备名会转换为安全名称。

## 预览速度与缓存

预览直接解码首张可用图片，在内存中缩小后编码 PNG，不再先导出原图到磁盘再读取。扫描完成时预先启动专用预览子进程，后续预览复用该进程；若扫描后立刻预览，首次仍可能需要等待依赖加载。多图资源包仅解码用于预览的图片，导出仍读取全部图片。

后台内存保留最多 64 MiB 的预览编码数据，按最近使用顺序淘汰。缩略 PNG 和原图尺寸/图片数量等元数据保存到 `temp/background-previews/`，因此预热全部后，早期素材即使被移出内存也能直接读取缩略图。重启程序后可继续复用磁盘缓存。

缓存按源文件完整路径、修改时间、创建/元数据变化时间、大小和预览尺寸区分；游戏资源变化后重新解码并替换旧缓存，损坏或不完整的缓存视为未命中。写入采用临时文件和原子替换，避免取消或退出留下半张缓存图片。全局清理缓存会同时删除背景缩略图，即使保留角色预览目录也会删除背景缓存；退出程序只释放内存和进程。

## 取消和失败处理

加载、预览、批量导出期间显示取消按钮。取消导出会终止提取子进程，保留已经完成的 PNG，并清理当前任务的临时编码文件。单个资源包或图片解码失败会记录到结果列表，其余素材继续导出；结束后界面显示失败项详情。

导出成功后累计导出次数按一次任务增加一次；全失败或取消的任务不增加次数。批量导出不自动重试整个任务，避免部分完成后重试产生重复图片。批量导出沿用提取 worker 的 45 秒无进度超时与 600 秒总超时。预览请求超时为 45 秒，取消或超时会终止专用进程，下次预览重新启动；单个素材解码失败不影响后续预览。程序退出时关闭预览进程。

## 实现位置

| 文件 | 职责 |
| --- | --- |
| `src/background_assets.py` | 目录定位、按相对路径建立素材 ID、自然排序、内存预览、LRU/磁盘缓存和 PNG 保存 |
| `src/worker_client.py` | 预览子进程预热、复用、取消、超时与退出清理；批量导出沿用单次 worker |
| `run.py` | `load_backgrounds` / `preview_background` / `prewarm_backgrounds` / `export_backgrounds` / `cancel_backgrounds` API、任务互斥与事件 |
| `backend.py` | `export_backgrounds` 单次 worker 和 `--background-worker` 专用预览入口；进度和完成结果走 stdio JSON |
| `webui/js/backgrounds.js` | 分类、搜索、勾选、预览和取消交互 |
| `webui/css/backgrounds.css` | 布局；标签页、按钮、下拉、列表和弹窗动画复用原版样式 |

素材扫描只枚举文件路径，按需预览/导出才解析 Unity bundle。含 Sprite 的包优先使用 Sprite 图像；没有 Sprite 时导出 Texture2D，避免同一精灵及其底层纹理重复出现。每个资源包处理后释放 UnityPy 数据，避免批量操作持续保留全部纹理。

背景任务使用现有提取锁，独立进度/完成事件为 `background_progress` / `background_complete`。提取期间禁止启动角色任务，避免共用状态栏和缓存清理发生冲突。界面复用 `MCE.createDropdown`、`MCE.showProgress`、`MCE.showModal` 和原版标签页切换；全局「禁用界面动画」仍然生效。

## 验证

安装项目已有的 Python 依赖后，从仓库根目录运行，无需游戏素材：

```powershell
python -m unittest discover -s tests -v
```

回归测试覆盖不同目录入口、不同 Unity 目录结构、自然排序、跨分类同名资源、Sprite/Texture2D 提取、像素与透明度保留、平铺和重名导出、部分失败继续、取消、无图像资源包、编码失败清理、内存缩略图、缓存失效与容量限制、磁盘缓存复用/损坏/写入失败、预热部分失败/取消/继续和清理，以及进程复用、取消/超时/异常退出后的恢复。

使用自己的游戏资源做集成验证时，检查三类素材可分别预览和导出、PNG 原始尺寸、素材行/键盘预览与独立勾选、跨分类选择、全部预热和取消、重启复用/清理缓存、导出取消和输出重名编号，以及开启/关闭动画和切换语言后的交互。测试素材、提取结果和本机游戏路径无需提交到仓库。
